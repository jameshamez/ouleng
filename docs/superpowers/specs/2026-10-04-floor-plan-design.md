# ผังร้าน + ลูกค้าเลือกโต๊ะเอง (Design)

ต่อจาก `2026-10-03-ouleng-line-ordering-design.md` — อนุมัติในแชท 2026-10-04

## ข้อมูล
- `tables` เพิ่ม `x, y, w, h` (หน่วยช่องในตาราง 24×18), `shape: round|square`, `active` (ลบ = ซ่อน)
- `floor_decor(id, kind, label, x, y, w, h)` — kind: `area | canal | stage | screen | counter | kitchen | entrance` (ดูอย่างเดียว)
- `bookings.table_id` ถูกกำหนดตอนจอง (ลูกค้าเลือก); `zone` = โซนของโต๊ะนั้น

## กติกา
- โต๊ะ "เหมาะ" กับกลุ่ม: `party ≤ seats ≤ party + 3`
- โต๊ะ "ถูกจอง": มีการจอง pending/confirmed/seated บนโต๊ะเดียวกัน วันเดียวกัน ห่างกัน < 2 ชม.
- เวลาที่เลือกได้ = มีอย่างน้อย 1 โต๊ะที่เหมาะและว่าง
- จองซ้อนไม่ได้: เช็กฝั่งเซิร์ฟเวอร์ + exclusion constraint ใน Postgres (`btree_gist`)
- ลบโต๊ะไม่ได้ถ้ามี session เปิดอยู่ หรือมีการจอง pending/confirmed วันนี้เป็นต้นไป
- รหัสโต๊ะต้องไม่ซ้ำในโต๊ะที่ active

## หน้าจอ
- ลูกค้า `/liff/book`: จำนวนคน → วัน → เวลา → ผัง (เลือกโต๊ะ) → ข้อมูลติดต่อ → สั่งล่วงหน้า
- แอดมิน → แท็บ "ผังร้าน": ลากวาง (snap ช่อง), ปรับขนาด, แตะแก้ข้อมูล, เพิ่ม/ลบ, บันทึก/ยกเลิกทีเดียว
- แคชเชียร์: ผังจริงแทนกริด + ป้าย "จอง HH:MM" เมื่อมีจองวันนี้ที่ยังไม่มาถึง
- การจอง: ปุ่ม "ลูกค้ามาถึง" เลือกโต๊ะที่จองไว้ให้ก่อน เปลี่ยนได้
